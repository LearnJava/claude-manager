## Честные оговорки

- n=2 на задачу-плечо: это тенденции, не статистика; 5 микрозадач по 40-160 с не экстраполируются на многочасовые сессии.
- Токены собраны по разным проводам (result-событие Claude Code vs turn.completed zcode), но оба считают ответы одного фасада api.z.ai.
- reasoning-токены: zcode отдаёт отдельным полем (здесь 0), Claude Code — внутри output.
- Попутная находка-баг менеджера: у GLM-сессий записи session_runs содержат 0 токенов — фасад зануляет usage ассистентских сообщений, а менеджер аккумулирует только их (internal/session/session.go:2060, EvtUsage); реальный usage есть только в result-событии и в run-строку не попадает. Метрики этого бенчмарка брались из session:result напрямую, так что выводы от бага не зависят.
