# Как проверить, что изменения из исследования работают

Исследование ([AI-agent-Windows-guide.ru.docx](AI-agent-Windows-guide.ru.docx)) предлагает изменения: короче
сессии, меньше вывода команд, UTF-8, один скрипт вместо цепочки вызовов. Этот документ — как измерить их
эффект: снять срез «до», внести изменение, через неделю снять срез «после» и сравнить.

## Коротко

1. **«До» уже снято 13.10.2026** (сессии до 12.10 включительно):
   [Lumen](measurements/2026-10-13-before-lumen/summary.md) ·
   [claude-manager](measurements/2026-10-13-before-claude-manager/summary.md).
2. **Через 7–10 дней** после изменения снять «после» и сравнить — две команды из раздела «Команды».
   Можно не запускать руками, а сказать Claude:
   > Выполни docs/Science_lab/MEASURE.md: сними срез «после» для Lumen и сравни с базовой линией.
3. **Не позже чем через ~30 дней**: Claude Code удаляет транскрипты старше 30 дней, менеджер — свои логи
   (`log_retention_days = 30`). Сохранённые срезы в `measurements/` не удаляются.

## Команды

Python — по полному пути (через алиас WindowsApps каждый запуск на 100 мс дольше). Из Git Bash в корне
репозитория claude-manager:

```bash
PY="C:/Users/konstantin/AppData/Local/Python/pythoncore-3.14-64/python.exe"
M=docs/Science_lab/claude-code-setup/tools/measure/measure.py

# 1. Срез «после»: сессии, начатые с 14.10 по сегодня (--since включительно, --until не включая)
"$PY" $M snapshot C:/kostja/Rust_Projects/Lumen_browser --since 2026-10-14 --label 2026-10-24-after-lumen

# 2. Сравнение «до» → «после» (таблица печатается и сохраняется в папку «после» как compare-*.md)
"$PY" $M compare docs/Science_lab/measurements/2026-10-13-before-lumen docs/Science_lab/measurements/2026-10-24-after-lumen
```

Для claude-manager — то же с путём `C:/kostja/GoProjects/claude-manager` и меткой `...-claude-manager`.
Для любого другого проекта — его путь: скрипт сам найдёт транскрипты в
`%USERPROFILE%\.claude\projects\<путь, где все не буквы и не цифры заменены на «-»>`.

| Команда | Что делает | Стоит токенов |
|---|---|---|
| `snapshot <проект> [--since Д] [--until Д] [--label имя]` | Срез затрат по транскриптам Claude Code: `metrics.json`, `summary.md`, `sessions.csv` и сырые `cost.json`, `by_length.json` в `measurements/<имя>/` | нет |
| `compare <срез до> <срез после>` | Таблица «до → после» по ключевым метрикам | нет |
| `speed` | Старт процесса и скорость счёта рантаймов на этой машине | нет, ~1 мин |
| `ab-script <файл> "<вопрос>"` | Один и тот же вопрос по файлу дважды через `claude -p`: одним скриптом и только Read/Grep. Ходы, секунды, $ | **да**, каждый прогон ограничен `--budget` (по умолчанию $1) |

`snapshot` запускает `cost_attribution.py` и `session_length_cost.py` из той же папки (методика
исследования) и добавляет к ним разбивку по ролям, долю нечитаемого вывода и число задач из
`history.db` менеджера.

В самом менеджере (после сборки ветки `exp-science-lab`) то же видно без скриптов: Experience →
«Стоимость по инструментам» — цена каждого вида вывода с перечитыванием и таблица «По длине сессии» с теми
же полосами (1–20 … 251+ ходов). Скрипты остаются для сравнения окон «до/после» и для проектов вне
менеджера.

## Что смотреть в сравнении

| Изменение | Метрика в `compare` | До, Lumen (13.10) | До, claude-manager | Ожидание |
|---|---|---|---|---|
| `git pull -q` в протоколе задач | git pull, ср. токенов на результат | 2 833 (67 вызовов) | 1 216 (8 вызовов) | < 100 |
| Правила kit: ограничивать вывод команд | grep / sed / cat, ср. токенов | 967 / 1 894 / 1 500 | 1 277 / 1 721 / 2 205 | ↓ |
| Правила kit: большие файлы диапазоном | Read *.md, ср. токенов | 4 517 | 3 350 | ↓ |
| UTF-8 в окружении сессий + правила kit | Нечитаемый вывод python, % | 8.6% (45 из 523) | 0 | ~1% |
| Передача задачи до 100 вызовов (handoff) | Затраты в сессиях >100 вызовов | 56.4% | 30.1% | ↓ |
| то же | Средний контекст на вызов | 117 081 | 86 885 | ↓ |
| то же | Вызовов на сессию, p90 | 129 | 41 | ≤ ~100 |
| то же | $ на вызов модели | $0.0412 | $0.0523 | ↓ |

Общие затраты в долларах сами по себе ничего не доказывают: они зависят от того, сколько работы было
сделано. Смотреть на удельные строки: $ на вызов, контекст на вызов, доли.

## Журнал изменений

Без журнала нельзя понять, какое изменение сдвинуло метрику. Каждое изменение — строка здесь, с датой,
с которой оно действует для **новых** сессий.

| Дата | Что изменено | Где | Какие метрики должны сдвинуться |
|---|---|---|---|
| 2026-10-13 | Базовая линия снята | `measurements/2026-10-13-before-*` | — |
| 2026-10-13 | **Kit установлен на эту машину**: правила в `~/.claude/CLAUDE.md` (UTF-8, Python по полному пути, ограничение вывода, большие файлы диапазоном, один скрипт), скилл `script-first`, `jobrun.exe`. Действует для всех новых сессий Claude Code | `%USERPROFILE%\.claude` (резервная копия `settings.json.bak-20261013-100317`; откат — `install.py --uninstall`) | grep / sed / cat и Read *.md — ср. токенов ↓; нечитаемый вывод ↓ |
| 2026-10-13 | `git pull -q` в протоколе задач — слито в master claude-manager и в main Lumen | claude-manager `6bb4b2a`; Lumen `7d0c8c24a` | git pull — ср. токенов < 100 |
| 2026-10-13 | `python_utf8 = true` — менеджер пересобран, ключ записан явно в `~/.claude-manager/config.toml` | claude-manager `8d68b90` | нечитаемый вывод python → ~1% |
| 2026-10-13 | `handoff_context_tokens = 150000` — включено у автономных сессий: Lumen S1–S6, claude-manager «Developer 1» (интерактивные Chat его не используют — так задумано) | claude-manager `8d68b90`; `<проект>/.claude-manager/config.toml` | затраты в сессиях >100 вызовов ↓, контекст на вызов ↓, p90 вызовов ≤ ~100 |
| 2026-10-13 | Вкладка «Стоимость по инструментам»: цена с перечитыванием и разбивка по длине сессии (LN-29) | claude-manager `af310cb` | не метрика, а инструмент: те же показатели прямо в приложении |

Новое изменение — новая строка с датой, с которой оно действует.

### Порядок окон

Все изменения включены одновременно 13.10, поэтому окно «после» одно — **с 14.10**:

```bash
"$PY" $M snapshot C:/kostja/Rust_Projects/Lumen_browser --since 2026-10-14 --label 2026-10-24-after-lumen
"$PY" $M compare docs/Science_lab/measurements/2026-10-13-before-lumen docs/Science_lab/measurements/2026-10-24-after-lumen
```

Вклад отдельных изменений всё равно читается по разным строкам `compare`: git pull — только `-q`;
grep / sed / cat / Read *.md — правила kit; нечитаемый вывод — `python_utf8` и kit; доля затрат в сессиях
>100 вызовов, контекст и $ на вызов — передача задачи (`handoff_context_tokens`). Следующее изменение —
своё окно `--since <дата>`.

## Как читать результат

- **Сравнивать похожую работу.** В `summary.md` есть разбивка по ролям (S1…S6, Chat): если до работал в
  основном S2 (WPT), а после — S3 (баги), общие цифры несравнимы, сравнивайте строки одной роли.
- **Мало сессий — вывод предварительный.** `compare` предупреждает, если в окне меньше 20 сессий.
- **Одно изменение — одно окно.** Если в одну неделю внесено несколько изменений, их вклад не разделить:
  поэтому журнал изменений и окна `--since`/`--until`.
- **Доллары — эквивалент цен API** (цены в `PRICES` в начале `cost_attribution.py`; обновлять при смене
  цен). На подписке это расход лимитов, а не счёт.
- **«≈ $ на задачу» — грубая оценка**: задачи считает менеджер (`history.db`), у ролей задачи разного
  размера (у S2 задача — одна страница WPT), а окна логов менеджера и транскриптов могут не совпадать.
  Смотреть тренд одной роли, а не абсолютное число.
- **Нечитаемый вывод — эвристика**: кракозябры cp1251 («РџСЂРёРІРµС‚»), серии символа замены U+FFFD,
  `UnicodeEncodeError`. Срабатывания проверены выборочно; абсолютное число может отличаться на несколько
  процентов, сравнение «до/после» корректно, потому что метод один.
- **Сегодняшний день (13.10) не входит ни в «до», ни в «после»**: в этот день вносились изменения.

## A/B «один скрипт против цепочки вызовов» (`ab-script`)

Проверяет главный вывод исследования про скрипты (там: 118 ходов / 317 с / $0.74 против 3 ходов / 47 с /
$0.077). Тратит токены — по умолчанию не больше $1 на прогон, два прогона на вариант ≈ до $4.

```bash
"$PY" $M ab-script <лог-файл> "Посчитай число строк с ошибками по дням и выведи топ-10 сообщений об ошибках" \
     --runs 2 --budget 1 --out docs/Science_lab/measurements/ab-script-<дата>.json
```

Сравнить: медианы ходов, секунд и $ по вариантам и **совпадение ответов** (оба ответа печатаются
полностью). Результат записать сюда:

| Дата | Файл | Вариант | Ходов | Секунд | $ | Ответ верный |
|---|---|---|---|---|---|---|
| 2026-10-13 | `~/.claude-manager/logs/app.log`, 712 КБ, sonnet | один скрипт | 4 | 17 | 0.091 | да |
| 2026-10-13 | то же | только Read/Grep | 56 | 166 | 0.312 | да |

13.10: один скрипт — в 14 раз меньше ходов, в 10 раз быстрее, в 3.4 раза дешевле при том же ответе
(вопрос: WARN/ERROR по дням и топ-10 `msg`; эталон посчитан отдельным скриптом, таблица по дням
совпала у обоих вариантов полностью). По одному прогону на вариант — разброс не оценён. Сырые данные —
`measurements/ab-script-2026-10-13.json` (в этом прогоне ответы обрезаны до 600 символов; с 13.10 скрипт
сохраняет их целиком).
