# lab-tools — инструменты исследования по уже записанным данным

Бесплатные, только чтение (`~/.claude-manager/history.db`, `~/.claude/projects`, `app.log`). Запуск: `python -I <скрипт>`.

| Скрипт | Что делает |
|---|---|
| `cache_write_split.py` | LAB-01: на что уходит запись в кэш — старт сессии или рост разговора |
| `window_model.py` | LAB-02: модель «Opus 1M против Sonnet с передачей», точка безубыточности |
| `weekly.py` | LAB-03: еженедельный пассивный отчёт по реальной работе |

## weekly.py

```
weekly.py [--since YYYY-MM-DD] [--weeks N] [--project NAME ...] [--out DIR]
```

Без аргументов — последние 4 недели по всем проектам из `session_runs.project`, отчёт в
`measurements/<сегодня>-weekly/RESULTS.md`, в stdout — сводка до 30 строк. `--project` — подстрока имени проекта
(без учёта регистра), можно повторять.

По неделям (окна по 7 дней, UTC) и проектам: на задачу — медианы и p90 по $, минутам, ходам, числу запусков
(сессий) и доле чтения/записи кэша; ворота (число, доля зелёных, минуты); фон (запуски без `task_ptr`, $ навыков);
потери (повторные чтения, пустые поиски, ошибки на 1000 вызовов). Каждая строка отчёта подписана таблицей-источником.
Каждая неделя сравнивается с предыдущей: стрелка и %, `!` — изменение больше 25% (шум пилота 20–30%).

Ограничения (они же в конце отчёта): задача = самый частый `task_ptr` запуска; `gate_runs` заполнена только для
части запусков, время ворот берётся из `app.log` (`process_exit` → `task_done`); «повторное чтение» и «пустой
поиск» — оценки по подписям действий.
