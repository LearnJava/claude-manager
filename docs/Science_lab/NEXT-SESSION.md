# Передача следующей сессии: как сократить расход токенов и ускорить выполнение задач

Ты решаешь, как проводить исследования по снижению расхода токенов и ускорению работы над задачами в Claude Manager.
Ниже: что уже известно, что решено, что нужно решить тебе, как проверять и чего не делать. Читать по порядку:
`AB-PILOT-2026-10-28.md` (факты), `docs/change-acceptance.md` (процесс приёмки), `ab-pilot-tools/README.md` (скрипты).

## Что известно

1. На последовательной работе над 5 задачами менеджер в конфигурации «включить всё» вдвое медленнее (≈195 против ≈95 мин)
   и вдвое дороже ($8,61 против $4,40) обычного Claude Code при равном качестве (скрытые тесты 80/80, 0 вмешательств).
2. Время: 39% (75 мин) ушло на ворота менеджера, которые идут после мерджа, дублируют прогон агента и не поймали
   ничего (11 из 11 зелёные). Остальное: 11 сессий вместо 5 и протокол (половина вызовов B).
3. Деньги: 47% стоимости B это запись контекста в кэш (≈$0,24 на сессию); накладные менеджера 25% (Chat $1,17, авто-навыки
   $0,91). Авто-навыки за всю историю: 31 попытка, 0 принятых, $10,17.
4. Накладных расходов у измерений, хуков и карточки менеджера нет (шаг не медленнее, +3K токенов на сессию).
5. Набор тестов вырос с 111 до 444 с за месяц (33 медленных теста дают 748 с, 76% добавлены после 14.10).
6. Пилот: n=1 на вариант, шум стоимости 20–30% (ворота ±24%). Это пилот, а не базовая линия.

## Что уже решено (не пересматривать без причины)

- Правило приёмки, карточка изменения, уровни L0–L3, лесенка R0 → R1: `docs/change-acceptance.md` §3–§5.
- Базовая линия = медиана n≥3 прогонов T5 для A и B-как-сегодня; пилот это прогон №1: §2 там же.
- Очередь гипотез H1–H7 с порогами: §6 там же. Всё новое выключено по умолчанию, пока карточка не закрыта.

## Что нужно решить тебе

1. **Порядок и бюджет.** Базовая линия ≈$9–10 и ≈3,5 ч, каждая карточка L2 ≈$2–5 и 1–2 ч. Запускать прогоны только с
   согласия пользователя.
2. **Параллельность.** Где менеджер может выиграть по времени: три разработчика против трёх параллельных обычных сессий
   (идея «follow-up run» из `PLAN.md` стенда), плюс работа без присмотра и восстановление. Как это мерить и чем
   делить машину (8 лог. CPU, один `go test ./...` занимает всё).
3. **L1 без токенов** для H1–H3: сценарии fakeclaude (ворота идут один раз, срез ворот не запускает, быстрый набор укладывается
   в бюджет). Как их оформить в `testdata/scenarios/`.
4. **Отделить функции от политики нарезки.** Лесенка R0 (всё выключено, один указатель) → по одной функции; что считать
   «всё выключено» (общие флаги затрагивают другие проекты: отдельный профиль или окно без других сессий).
5. **Авто-навыки и experience tracking:** выключать по умолчанию сразу или после карточки.
6. **Хранение результатов:** таблица в `docs/change-acceptance.md` §2 и §7, данные в `docs/Science_lab/measurements/<дата>-<имя>/`.

## Как проверить утверждения пилота

| Утверждение | Как проверить |
|---|---|
| ворота 75 мин, 11 из 11 зелёные, после мерджа | `ab-pilot-tools/analyze_speed.py` (ворота = выход процесса → `task_done`); `select count(*), sum(passed) from gate_runs where project='bench-cm'` в `~/.claude-manager/history.db` |
| $ по категориям, запись кэша 47% | `ab-pilot-tools/cost.py` (читает `measurements/2026-10-28-ab-pilot/bench.json`) |
| шаг не медленнее, пауза менеджера 1–2 с | `ab-pilot-tools/latency.py`; пауза: `task_done` → `session.spawned` в `app.log` |
| протокол ≈ половина вызовов, ходы до первой записи | `ab-pilot-tools/calls.py` |
| начальный контекст, фоновые сессии = авто-навыки | `ab-pilot-tools/audit.py`; `select status, origin, count(*), sum(cost_usd) from skills group by 1,2` |
| набор тестов 7,4 мин, 33 медленных теста | `go test -count=1 -json ./... > gotest.json; python -I ab-pilot-tools/slow.py gotest.json` |
| рост набора тестов 111 → 444 с | цикл по коммитам из `ab-pilot-tools/README.md` (26.09 `bf278a2`, 14.10 `c03c875`, 24.10 `9470fa8`, 28.10 `001193b`) |
| качество 80/80, ревью, Playwright | `cm-bench/_kit/RESULTS.md`; приватные оценки стенда (путь в `_kit/PLAN.md`) |
| «раньше было быстрее» не подтверждается | недельные медианы `session_runs` по сессиям (`AB-PILOT-2026-10-28.md`, раздел про гипотезу) |

Транскрипты Claude Code живут около 30 дней (до ~27.11.2026): после этого пересчитать нельзя, остаются
`bench.json`, `RESULTS.md` и таблицы в документах.

## Ограничения

- Не менять пилотные клоны `cm-bench/a`, `b`, `_logs/`, `runs_a.jsonl`, `events.jsonl` и проект `bench-cm` в менеджере.
- Скрытые тесты, их пути и пороги не класть в репозиторий и в клоны, которые видят агенты.
- Один прогон за раз; не запускать `go test ./...` параллельно с замером.
- Не убивать и не перезапускать `claude-manager.exe` из сессии (guard-self-kill). После перезапуска приложения токен
  MCP-клиента даёт 401: перезапустить клиент.
- Прогоны платные: деньги и время согласовывать.
