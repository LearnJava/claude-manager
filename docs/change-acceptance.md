# Приёмка изменений: ничего не принимается без подтверждения на стенде

Изменение Claude Manager, которое влияет на скорость, токены или качество работы сессий, принимается только если
на стенде показан эффект больше шума и качество не упало. Порог задаётся **до** прогона (как «правило вердикта» в
`cm-bench/_kit/PLAN.md`). Всё новое выключено по умолчанию, пока карточка не закрыта: при выключенном флаге
поведение побайтно прежнее (инвариант LEARN-TASKS).

Основание: пилот A/B 28.10.2026 показал, что при конфигурации «включить всё» менеджер на последовательной работе
в 2 раза медленнее (195 против ~95 мин) и в 2 раза дороже ($8,61 против $4,40) обычного Claude Code при том же
качестве на T5. Главные причины: ворота после мерджа (39% времени, ни одной поимки), нарезка 5 задач на 11 сессий,
накладные менеджера (Chat, авто-навыки), рост набора тестов (7,4 мин вместо 1,9 мин за месяц). Подробности пилота:
`docs/Science_lab/AB-PILOT-2026-10-28.md`; передача следующей сессии: `docs/Science_lab/NEXT-SESSION.md`.

## 2. Базовая линия

Базовая линия = медиана n≥3 прогонов варианта на тяжёлой задаче (T5), разброс = (max−min)/медиана. Полный бенч
(T1..T5 × A, B) гоняется перед включением изменений по умолчанию, раз на пачку изменений.

Пилот 28.10 это прогон №1, а не базовая линия: A на T5 20,7 мин, $1,60, скрытые тесты 22/22; B на T5 ≈79 мин (агент ≈51,
ворота ≈27), $2,48, 22/22. Известный шум: время одних и тех же ворот 5,1–9,6 мин (±24%) при одном коде; A и B шли
параллельно с 17:57 до 19:12. Скрытые тесты по пилоту прогнаны: 80/80 у обоих (T1 6, T2 8, T3 14, T4 30, T5 22).
Недостаёт: ещё по 2 прогона T5 для каждого варианта.

4. Тексты: `tasks/A-T5.txt` есть; `tasks/B-chat-T5.txt` = `B_PREFIX` из `compose.py` + текст T5 (нарезку делает Chat,

## 4. Уровни проверки

- **L0.** Тесты репозитория, ворота зелёные.
- **L1.** Механизм без модели: сценарий fakeclaude/testkit с утверждениями (ворота идут один раз, срез ворот не
  запускает, быстрый набор укладывается в N минут и покрывает затронутые пакеты). Токены не тратятся, минуты.
- **L2.** Стенд: T5, «до» и «после» по 2–3 повтора, последовательно, в условиях из §1.
- **L3.** Полный бенч перед включением по умолчанию.

## 5. Правило приёмки

Принять, если выполнено всё:
1. скрытые тесты не хуже базы, ворота зелёные;
2. целевая метрика лучше базы больше чем на max(15%, 2×разброс);
3. охранные метрики: стоимость не выше +10%, вмешательства 0, время других задач не хуже;
4. на L1 механизм работает ровно как заявлено.

Иначе флаг остаётся выключенным, карточка закрывается «отклонено» или «доработать». Причинность между несколькими
изменениями проверяется лесенкой: R0 «всё выключено, один указатель», затем включаем по одному.
