# Завершение сессии после маркера готовности (EX-01)

Очередь: [STATUS-P1.md](./STATUS-P1.md).

## EX-01: принудительно завершать CLI, не вышедший после маркера готовности

**Depends on:** —

**Files:** `internal/session/session.go` (цикл чтения stdout около `turnExitNotice`, ~строки 1396 и 1653–1690), тест рядом (`internal/session/*_test.go`), `docs/design-decisions.md`.

**Проблема (установлена 2026-10-18 на `Lumen browser/S6`).** Автономная сессия закончила ход с маркером готовности (`session.question_auto` → `handleLine` вернул `true`), менеджер закрыл stdin, но `claude -p` не вышел: у него осталась фоновая Bash-команда (CLI сам перевёл её в фон по таймауту 120 с — `grep -rn … .` по каталогу с `target/`). Через 30 с менеджер только пишет информационное сообщение (`session.exit_wait`) и ждёт. Процесса `process_exit` нет, статус остаётся `working`, `task_done` не срабатывает, следующая сессия из очереди не стартует — до 30 минут (таймаут фоновой задачи CLI), а при зависшей команде и дольше.

**What to do:**
1. Различать два случая после `finished`:
   - ход закончился с `KindContinueSession` (маркер готовности, `continueMarkerHit`) — задача по определению закрыта, ждать фоновую команду нет смысла;
   - обычный `result` без маркера — поведение не менять (CLI может продолжить сам, когда фоновая команда закончится).
2. Для маркера готовности добавить второй таймер `turnExitGrace` (по умолчанию 60 с после `turnExitNotice`, вынести в `var`, чтобы тест подменял). По срабатыванию: записать в лог сессии системную строку «CLI не вышел через N с после маркера готовности — завершаю принудительно (фоновая команда: …)», `logger.L.Warn("session.exit_force", …)`, и завершить дерево процессов CLI тем же способом, каким это делает `Stop`/restart (не изобретать новый; убить надо `claude.exe` вместе с детьми — bash, cm-mcp). Дальше обычный путь: `scanner` получает EOF, `cmd.Wait`, `process_exit`, `task_done`, запуск следующей сессии.
3. Таймер останавливать, если CLI вышел сам, и перевзводить на каждый `result` (как `exitNotice`).
4. Не трогать менеджер: никакого завершения `claude-manager.exe` и ничего за пределами дерева этой сессии.
5. Тест: fake-CLI (fakeclaude), который после маркера готовности не выходит и не закрывает stdout; с `turnExitNotice`/`turnExitGrace` по 50–100 мс сессия переходит в завершённое состояние, `task_done` засчитан. Второй тест: тот же fake-CLI, но результат без маркера — процесс **не** убивается.
6. В `docs/design-decisions.md` (раздел про автономные сессии/завершение хода) — одной-двумя фразами: после маркера готовности зависший CLI добивается через `turnExitGrace`, фоновые команды в этом случае не ждём.

**Done when:**
- `go build ./... && go vet ./... && go test ./...` зелёные; тест из п. 5 падает на старом коде.
- В работающем менеджере сессия, оставившая фоновую команду и закончившая ход маркером готовности, сама завершается и следующая задача из очереди стартует без ручного «Перезапуска».
- Строка EX-01 в Status ниже — `✓ DONE`, указатель удалён из `STATUS-P1.md`.
