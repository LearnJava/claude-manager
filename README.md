# Claude Session Manager

Настольное приложение для Windows и Linux, которое держит несколько Claude Code
одновременно — в разных проектах, каждый за своей очередью задач — и следит, чтобы они
не ломались, не ходили по кругу и не жгли лимит впустую.

Запускалок параллельных сессий хватает и без него. Этот менеджер про другое: чтобы
работа шла **сама**, пока ты занят другим, и чтобы было видно, куда ушли время и лимит.

---

## Зачем он нужен

Одна сессия Claude Code — это помощник, который работает ровно до тех пор, пока ты на
него смотришь. Стоит отвернуться, и он:

- упёрся в вопрос «можно выполнить эту команду?» и ждёт;
- забил контекст и начал терять нить;
- залип, повторяя один и тот же вызов по кругу;
- поймал лимит и замолчал;
- закончил задачу и остановился, хотя в очереди ещё десять.

Менеджер закрывает каждую из этих дыр. Ты один раз описываешь, **кто** работает и
**откуда берёт задачи**, а дальше возвращаешься к сделанной работе и к понятному отчёту,
что происходило.

---

## Как здесь всё устроено

Это важно понять до первого запуска — одно понятие здесь работает не так, как ожидаешь.

**Проект** — папка с кодом.

**Сессия** — постоянный работник в этом проекте. В её промпте пишется **не задача**, а
кто это и по каким правилам он живёт: «ты программист, задачи берёшь из очереди,
работаешь по протоколу из `docs/git-workflow.md`». Этот текст одинаков для всех задач,
которые сессия когда-либо возьмёт, и меняется редко. Именно промптом сессии отличаются
друг от друга: одна — программист на Rust, другая — ревьюер, третья — просто чат.

**Очередь** — обычный текстовый файл, который ты указываешь в поле «Файл источника
задач» (например `STATUS-P1.md`). Внутри лежат только строки-указатели вида
`ROADMAP.md:51` — файл с задачами и номер строки, с которой начинается нужная. Верхняя
строка — следующая задача в работу.

**Файл задач** — `ROADMAP.md` или любой `*-TASKS.md`, где каждая задача описана
по-человечески: зачем она, что сделать, что считается готовым результатом.

**Цикл работы:** сессия берёт верхний указатель → открывает по нему описание задачи →
делает → по готовности убирает указатель из очереди → берёт следующий. Очередь
опустела — сессия останавливается сама.

**Рабочая папка.** Если включить «Использовать git worktree», у сессии появится
постоянная отдельная копия проекта. Так несколько сессий могут работать в одном проекте
одновременно, не наступая друг другу на руки, а незаконченная задача спокойно
продолжается в той же папке после перезапуска.

Отдельно стоит **«Просто чат»** — обычная сессия без всякой очереди, где ты даёшь
указания напрямую. Нужна для разовых дел: обсудить, разобраться, поправить один файл,
написать тот самый файл с задачами.

## Как завести проект с нуля

Весь путь проходится мышкой, ничего не нужно писать в конфиги руками.

### 1. Добавить проект

Кнопка **+** в панели **Projects** слева (или **Настройки → Проекты → + Добавить
проект**). Укажи имя и путь к папке.

Если в папке ещё нет git-репозитория, приложение предложит его создать.

### 2. Дать проекту контекст

Если в проекте нет `CLAUDE.md`, появится подсказка: «В проекте нет CLAUDE.md — сессии
стартуют без контекста». Рядом кнопка, которая запускает служебную сессию **Init**: она
осмотрит проект и напишет этот файл сама. `CLAUDE.md` — то, что Claude читает первым
делом в каждой сессии: из чего состоит проект, чем собирается, какие в нём правила.

Без него работать можно, но каждая сессия будет начинать со знакомства с проектом
заново, тратя на это контекст и время.

### 3. Поставить протокол работы

**Настройки → Проекты → Протокол сессии → установить.**

В проект запишутся `docs/git-workflow.md` (правила: как брать задачу, в какой ветке
работать, как завершать), `scripts/worktree-pool.sh` и два навыка — `/cm-task-start` и
`/cm-task-finish`, которыми сессия пользуется сама. Существующие файлы **никогда не
перезаписываются**: если у проекта уже есть свой протокол, он останется.

Этот шаг нужен, если сессия будет работать в отдельной рабочей папке и вести ветки
задач. Для «просто чата» он не обязателен.

### 4. Завести задачи

Два пути, оба рабочие.

**Автоматически:** **Настройки → Проекты → Сгенерировать дорожную карту с помощью ИИ.**
Приложение разберёт проект, предложит план, и ты увидишь его в окне разбора: шаги можно
переставлять, править и удалять, сразу видна ориентировочная стоимость и время.
Подтверждаешь — и в проекте появляются два файла: `ROADMAP.md` с подробным описанием
задач и `STATUS-P1.md` с очередью-указателями. Потом дорожная карта видна прямо в панели
сессии деревом с процентом готовности.

**Руками через чат:** нажми **«Просто чат»** у проекта и попроси составить план работ —
файл с задачами и очередь к нему. Способ удобнее, когда ты уже знаешь, что хочешь, и
тебе нужна не идея, а аккуратно оформленный список.

Формат простой, его легко вести и самому: в файле задач — заголовки задач с описанием, в
файле очереди — строки `ИМЯ-ФАЙЛА.md:НОМЕР_СТРОКИ`, по приоритету сверху вниз.

### 5. Создать сессию

**Настройки → Сессии → + Добавить.** Заполняются четыре важных поля:

| Поле | Что писать |
|---|---|
| **Промпт** | Кто это и по каким правилам работает. Например: «Ты программист. Задачи берёшь из очереди. Работаешь по протоколу из `docs/git-workflow.md`». Не задача — роль |
| **Файл источника задач** | `STATUS-P1.md` — та самая очередь. Если оставить пустым, очереди нет и сессия будет обычным чатом |
| **Автоперезапуск после задачи** | Включить, если нужно, чтобы она сама брала следующую задачу, а не останавливалась после первой |
| **Использовать git worktree** | Включить, если сессий в проекте несколько или задачи ведутся в отдельных ветках |

Там же выбираются модель и уровень усилия, режим разрешений, максимум задач за запуск и
лимит расхода.

### 6. Запустить

**Save**, затем `▶` рядом с сессией. Лог пойдёт в главном окне в реальном времени.

Дальше всё мышкой: навёл на проект — запустить или остановить все его сессии, навёл на
сессию — её одну. Кнопка остановки вежливая: сессия сначала доводит текущую задачу и
только потом выходит.

## Что он умеет

### Несколько сессий сразу — и это правда быстрее

Каждая сессия живёт в отдельном процессе, со своей рабочей папкой, своей моделью и
своими правами. Пока одна ждёт сборку, тесты или твой ответ, остальные работают — на
живых проектах параллельные сессии окупаются полностью, потому что большую часть времени
агент не считает, а **ждёт**.

### Не даёт сессии умереть

- **Контекст заканчивается** — сессия перезапускается сама и получает короткую выжимку:
  что уже сделано, что осталось. Не с чистого листа, а с того же места.
- **Пошла по кругу** — менеджер замечает повторяющиеся одинаковые вызовы и вмешивается,
  а не смотрит, как сгорает окно.
- **Упёрлась в лимит** — дождётся и продолжит сама, не потеряв задачу. При желании можно
  не ждать, а сразу переключаться на запасную модель.
- **Приложение упало** — сессии и логи восстанавливаются после запуска.

### Разрешения не стопорят работу

Запрос появляется баннером прямо в окне сессии, все ожидающие собраны в общей очереди, а
то, что ты одобряешь постоянно, описывается один раз правилом — дальше одобряется само.

### Бесплатные руки

Отдельный режим: Claude составляет самодостаточное техзадание, внешние бесплатные модели
пишут по нему код заплатками, менеджер прикладывает их в изолированной копии проекта,
прогоняет сборку и тесты и возвращает дефекты обратно — до трёх кругов. Судит не чьё-то
мнение, а тесты: их нельзя уговорить. В конце — сравнительный отчёт, какой модели сколько
кругов нужно и чьи заплатки вообще прикладываются.

Приятное следствие: эти модели **не трогают лимит Claude**. Он тратится только на то,
чтобы думать и проверять.

### Учится на твоих ошибках

Менеджер ведёт журнал всех действий сессий. Повторяющиеся ошибки собираются в группы, из
них рождается правило — «вот так в этом проекте делать не надо, надо вот так». Правило не
внедряется молча: оно уходит на испытание, эффект замеряется, стало хуже — откатится
само. Так же из повторяющихся удачных последовательностей рождаются навыки.

### Видно, куда всё уходит

История всех запусков с фильтрами и выгрузкой, расход по дням и проектам, эффективность
кэша, состояние лимита, экспорт любого лога в удобном формате.

### Управляется из другого ИИ

Любой MCP-клиент — Claude Code, Claude Desktop, Cursor — может делать с менеджером всё то
же, что делаешь ты руками: заводить проекты, запускать сессии, отвечать на запросы
разрешений, читать логи и отчёты.

### Подбор модели под задачу (по желанию)

По умолчанию выключено: модель берётся та, которую ты выбрал для сессии. Если включить
**Настройки → Global → Auto model routing**, то при ручном запуске отдельной сессии
менеджер сперва быстро и дёшево разберёт задачу и предложит модель с уровнем усилия —
согласиться или переопределить решаешь ты. На автоматические перезапуски и на «запустить
все» это не распространяется: там всегда модель из настроек сессии.

## Чем он отличается от остальных

**От «запускалок» параллельных сессий.** Они дают отдельную копию проекта на задачу и
просмотр изменений — и это уже почти встроено в сам Claude Code. Менеджер начинается
там, где они заканчиваются: он следит за здоровьем сессии, а не только за её запуском.

**От облачных фабрик.** Они работают на чужом железе и твою машину не видят: ни
локальных тестов с видеокартой, ни твоих инструментов, ни твоего окружения. И они не
заинтересованы показывать, сколько потрачено впустую — расход это их выручка. Здесь всё
наоборот: работа идёт у тебя, а перерасход никому не выгоден.

**От систем наблюдения за ИИ.** Они отвечают на вопрос «кто сколько потратил», но не
связывают расход с результатом. Здесь расход привязан к сессии, задаче и конкретной
команде, которая его вызвала.

**Главное отличие.** Ни один из них не отвечает на вопрос, который решает всё: **какая
часть работы была бесполезной**. Повторно прочитанные файлы, поиски без результата,
перечитывание одного и того же по кругу. По нашим замерам именно на это уходит большая
часть окна — и именно это менеджер учится показывать и резать.

## К чему стремимся

Чтобы менеджер не просто гонял агентов, а делал их дешевле и толковее с каждой неделей.
Ближайшие шаги:

1. **Показать потери.** Отчёт, в котором видно: столько-то работы было впустую, вот
   какой именно, вот в каких сессиях.
2. **Мерить в том, что действительно кончается.** На подписке дефицит — не деньги, а
   окно лимита и время. Главная цифра должна быть не «сколько стоило», а «сколько задача
   съела у твоего окна».
3. **Запрещать, а не уговаривать.** Выученное правило в тексте подсказки модель может и
   забыть. Запрет, срабатывающий до выполнения команды, не забывается никогда и не стоит
   ни одного токена.
4. **Помнить тупики дольше одной сессии.** Если на этом месте уже застревали — сказать,
   что в прошлый раз помогло.
5. **Одинаково строгая проверка для всех.** Сейчас бесплатные внешние модели проходят
   обязательную проверку сборкой и тестами, а сам Claude — нет. Это надо выровнять.

Подробный план — [WASTE-TASKS.md](./WASTE-TASKS.md).

## Что нужно для запуска

Установленный [Claude Code CLI](https://claude.ai/code) — всё остальное приложение берёт
на себя. Работает на Windows и Linux; на Windows есть значок в системном трее, и крестик
окна прячет приложение туда, не останавливая сессии (полный выход — пункт **Quit** в меню
трея). На Linux трея нет, и закрытие окна завершает работу приложения.

Как альтернативу Claude Code CLI сессия может использовать Hermes CLI — тогда доступны
модели любого провайдера, но оплачиваются они отдельно, а не из подписки Claude.

**Полезно знать:**

- `Ctrl+1` … `Ctrl+4` — переключение между первыми четырьмя сессиями, `Ctrl+F` — поиск по
  логу, `Escape` — закрыть диалог.
- Настройки сохраняются только по кнопке **Save** — просто закрыть окно недостаточно.
- Все настройки лежат обычным текстовым файлом в `~/.claude-manager/config.toml`: его
  можно править руками и заглянуть туда, если что-то удалил по ошибке.

## Если что-то пошло не так

**Сессия стоит и ничего не делает.** Скорее всего ждёт разрешения — проверь баннер в окне
сессии и очередь разрешений в строке состояния.

**Сессия сразу остановилась и не взяла ни одной задачи.** Проверь поле «Файл источника
задач»: путь должен указывать на файл очереди внутри проекта, а в самом файле должны
лежать строки-указатели на задачи. Пустая очередь — законный повод остановиться.

**Указатель открывает не ту задачу.** Номера строк сдвигаются, когда в файл задач
дописывают текст выше. Новые задачи безопаснее добавлять в конец файла, а после правок
середины — проверять, что строка по указателю всё ещё заголовок нужной задачи.

**Сессии мешают друг другу в одном проекте.** Включи «Использовать git worktree» — у
каждой появится своя рабочая папка. Если приложение предупреждает, что протокола нет,
поставь его из **Настройки → Проекты**.

**Настройки не применились.** Нажми **Save** — в файл пишется только явным сохранением.

**Удалил проект случайно.** Открой `~/.claude-manager/config.toml` — там последняя
сохранённая версия.
