# Старт задачи — протокол claude-manager

$ARGUMENTS — короткое имя задачи в kebab-case (например `ln02-signatures`).
Если не передан — определи из указателя, который берёшь, и назови по номеру
задачи.

Полный протокол — [docs/git-workflow.md](../../../docs/git-workflow.md).

## Шаг 1 — Синхронизируйся и посмотри, что уже занято

```bash
git pull origin master
git branch -a
```

**Резервация задачи — это сама ветка `p<N>-…`**, никакого реестра «в работе»
нет. Указатель в `*-STATUS.md` остаётся на месте до завершения задачи.

- Ветка `p<N>-…` **твоя и незакончена** → это твоя прерванная задача.
  **Продолжай ЕЁ**, новую не создавай и другую задачу не бери. Что именно
  сделано — смотри по `git log <branch>` и `git diff master..<branch>`, а не по
  памяти: предыдущая сессия могла оборваться в любой момент.
- Ветка чужая (другой `p<N>-`) → задача занята, возьми следующий указатель.

## Шаг 2 — Возьми задачу из очереди

Верхний указатель `<файл>:NN` из своего `*-STATUS.md`, все зависимости которого
уже `✓ DONE`. Строго сверху вниз — порядок кодирует зависимости, а не удобство.
Отметь задачу `● IN PROGRESS` в таблице Status её мастер-файла (эта правка
поедет в ветке, не в master).

## Шаг 3 — Займи слот пула

Не создавай worktree на задачу — занимай свой постоянный слот:

```bash
cd "$(bash scripts/worktree-pool.sh p<N>-work p<N>-$ARGUMENTS | tail -1)"
```

Дальше работа ведётся **только** в слоте. Если скрипт отказал (незакоммиченная
или невлитая работа в слоте) — не форсируй: разберись, что там лежит, это чья-то
незавершённая задача.

Менеджерский флаг `use_worktree` для такой сессии должен быть `false` — иначе
рядом появится второй, безымянный worktree от HEAD, и работа снова разъедется.

## Шаг 4 — Опубликуй ветку (это и есть резервация)

До первой правки кода:

```bash
git push origin p<N>-$ARGUMENTS
```

## Шаг 5 — Сообщи пользователю

Какую задачу взял, какая ветка, какой слот, продолжение это или новый старт.
