# Руководство пользователя — Claude Session Manager

Это руководство для человека **без опыта программирования**. Всё, что здесь написано,
сверено с исходным кодом программы — названия кнопок, значения по умолчанию и поведение
описаны так, как они реально работают.

> Интерфейс программы на английском языке. В руководстве английские надписи приводятся
> как есть (например, **Start after task**), а рядом — объяснение по-русски.

## 1. Что делает программа

**Claude Session Manager** — «пульт управления» для умного помощника-программиста
**Claude**. Программа позволяет запускать сразу нескольких таких помощников, следить за
их работой в реальном времени, разрешать или запрещать им действия, останавливать и
перезапускать, а также видеть расходы.

Каждый запущенный помощник называется **сессией**. Папка с вашим проектом — **проектом**.
У одного проекта может быть несколько сессий.

> Claude — платный сервис. Каждый шаг стоит небольших денег. Программа показывает
> текущие и накопленные расходы, чтобы не было сюрпризов.

---

## 2. Главные понятия

- **Проект** — папка на компьютере, над которой работает помощник.
- **Сессия** — один запущенный помощник со своим заданием.
- **Задание (prompt)** — текст с описанием, что нужно сделать.
- **Модель** — «мозг» помощника. Основные:
  - **haiku** — быстрый и дешёвый (простые задачи);
  - **sonnet** — средний, универсальный (**значение по умолчанию**);
  - **opus** — самый умный и дорогой (сложные задачи).
- **Effort (усилие)** — насколько тщательно помощник думает: `low`, `medium`, `high`
  (**по умолчанию `high`**), `xhigh`, `max`. Больше усилий — дольше и дороже.
- **Permission mode (режим разрешений)** — насколько самостоятельным будет помощник
  (по умолчанию `acceptEdits` — см. раздел 8).
- **Разрешение (permission)** — согласие пользователя на действие помощника.

Все настройки хранятся в одном файле на диске:
**`C:\Users\ваше-имя\.claude-manager\config.toml`**. Его можно менять прямо в программе
через **Settings**, руками лезть в файл не нужно.

## 3. Как устроено окно

```
┌──────────────────────────────────────────────────────────────────────┐
│ Claude Session Manager              [Mixed] [Dashboard] [History] [Settings] │ ← верхняя полоса
├──────────────────┬───────────────────────────────────────────────────┤
│                  │                                                     │
│  Список          │            Панель выбранной сессии                  │
│  проектов        │   (заголовок с метриками, кнопки управления,        │
│  и сессий        │    «прямой эфир» работы, поле для сообщения)         │
│  (слева)         │                                                     │
│                  │                                                     │
├──────────────────┴───────────────────────────────────────────────────┤
│ Active: 1/3   ⚠ Waiting: 0   Cost today: $0.42   Uptime: 12m           │ ← строка состояния
└──────────────────────────────────────────────────────────────────────┘
```

- **Верхняя полоса.** Слева заголовок «Claude Session Manager». Справа четыре кнопки
  (именно в таком порядке): **Mixed**, **Dashboard**, **History**, **Settings**.
- **Слева** — список проектов и сессий, отсюда всё запускается.
- **По центру** — панель выбранной сессии. Если ничего не выбрано, там надпись
  *«Select a session from the sidebar»*.
- **Внизу** — строка состояния (сколько работает, кто ждёт, расходы за день).
- **Границу между списком и центром можно тянуть мышью** (ширина от 150 до 500 пикселей).

## 4. Быстрый старт: первая сессия за 5 шагов

1. **Добавьте проект.** В списке слева нажмите **`+`** (подсказка «Add project») — или
   **Settings → Projects → + Add project**. Укажите **Name** (любое имя) и **Path** (путь
   к папке; можно нажать **Browse…** и выбрать мышью).
2. **Добавьте сессию.** Откройте **Settings → Sessions**, выберите проект и нажмите
   **+ Add**. Заполните **Name** (например, `S1`) и **Prompt** (задание обычными словами).
3. **Сохраните.** Нажмите **Save** внизу окна настроек. *Без нажатия Save изменения не
   сохранятся.*
4. **Запустите.** В списке слева наведите мышь на сессию и нажмите **`▶`**.
5. **Наблюдайте.** В центре побежит «прямой эфир»: что помощник читает, пишет и делает.

Для самой первой сессии оставьте значения по умолчанию: модель **sonnet**, effort
**high**, режим разрешений **acceptEdits**.

## 5. Боковая панель: проекты и сессии

Вверху панели — заголовок **Projects** и кнопка **`+`** (добавить проект).

### Строка проекта

- Слева стрелка **`▶`/`▼`** — свернуть/развернуть список сессий проекта.
- При наведении справа появляются кнопки:
  - **`▶`** (подсказка «Start all») — запустить **все** сессии проекта. При запуске
    нескольких сессий они стартуют не разом, а с паузой в несколько секунд между ними
    (для экономии — «прогрев кэша»).
  - **`■`** (подсказка «Stop all») — остановить все сессии проекта.
  - **`✕`** — удалить проект. **Удаление в два клика:** первый клик превращает кнопку в
    красный **`?`** («Click again to confirm delete»), второй клик в течение ~3 секунд
    удаляет. Если передумали — просто подождите, всё отменится само.

> Почему в два клика? В окне программы обычное окно-подтверждение не работает, поэтому
> защита от случайного удаления сделана двойным нажатием.

### Строка сессии

- Слева **цветной кружок-статус** (см. раздел 7). При ожидании разрешения он **мигает**.
- Имя сессии и её время работы (uptime).
- При наведении появляется кнопка **`▶`** (запустить) или **`■`** (остановить).

## 6. Панель сессии: что видно и чем управлять

Когда сессия выбрана, в центре показывается её панель.

### Заголовок с метриками

- Кружок-статус, имя сессии, «— проект», текстовый статус и время работы.
- **Branch** (ветка git, если есть), **Task** (текущая задача, если есть),
  **Turns** (число «ходов»), **Tokens: … in / … out** (объём обработанного текста),
  **Model** (используемая модель).
- **Cost** (стоимость), **Cache hit** (эффективность кэша, в процентах) и **полоса
  заполнения контекста** с процентом.

### Кнопки управления

| Кнопка | Надпись/подсказка | Что делает |
|---|---|---|
| ⏹ | **Stop** — «terminate the process now» | Немедленно остановить процесс |
| ⏹ | **Stop after task** — «let the current task finish, then stop» | Мягкая остановка: дождаться конца задачи |
| 🔄 | **Restart** | Остановить и запустить сессию заново |
| 📋 | **Copy log** | Скопировать журнал (покажет «✓ Copied») |
| 🗑 | **Clear log** | Очистить журнал на экране (в хранилище история остаётся) |
| 💾 | **Export log** | Сохранить журнал в файл |

Рядом с **Export log** — выпадающий список формата: **Markdown**, **JSON** или **Text**.
После сохранения появится строка «Saved → путь к файлу».

### Журнал («прямой эфир»)

- Строка поиска с подсказкой **«Filter log… (Ctrl+F)»** — фильтрует журнал по мере ввода
  и показывает счётчик «совпадения/всего». Крестик очищает, **Escape** — тоже.
- Журнал **сам прокручивается вниз**. Если вы прокрутили вверх, появится кнопка
  **«↓ Jump to latest»** (вернуться к последним строкам).

### Поле сообщения

Внизу — поле ввода с подсказкой **«Type a message — Enter to send, Shift+Enter for
newline»**. Напишите сообщение помощнику и нажмите **Enter** (или кнопку **Send ▶**).
**Shift+Enter** — перенос строки. Если сессия не запущена, поле показывает «Session is
not active» и неактивно.

## 7. Статусы сессии

Полный список состояний (как они называются в программе):

| Статус | Что означает |
|---|---|
| **idle** | Простаивает, не работает |
| **starting** | Запускается |
| **analyzing** | Идёт предварительный анализ задачи |
| **working** | Работает над задачей |
| **waiting_permission** | Ждёт вашего ответа на запрос разрешения |
| **rate_limited** | Сервис временно ограничил скорость — идёт пауза |
| **retrying** | Восстановление после временной ошибки |
| **stopping** | Останавливается |
| **error** | Произошла ошибка |

## 8. Запросы разрешений

Иногда помощник хочет выполнить важное действие (например, команду) и **спрашивает
согласия**. Пока вы не ответите, сессия стоит в статусе **waiting_permission** и не
двигается дальше.

Как это выглядит:

- Прямо в окне сессии появляется **баннер** с описанием действия, уровнем риска
  (🔴 высокий / 🟡 средний / 🟢 низкий) и кнопками.
- Все ожидающие запросы собраны в **Permission Queue** (очередь разрешений). Открыть её
  можно кликом по **«⚠ Waiting: N»** в нижней строке состояния.

### Кнопки в баннере

| Кнопка | Что делает |
|---|---|
| **✓ Allow** | Разрешить **только этот** запрос |
| **✗ Deny** | Запретить **только этот** запрос |
| **✓ Allow similar** | Разрешить этот и похожие — до перезапуска программы (правило в памяти) |
| **✓ Always allow** | Разрешить и **запомнить навсегда** (правило сохраняется в настройки) |
| **✗ Always deny** | Запретить и **запомнить навсегда** |

В очереди (Permission Queue) на каждый запрос есть **✓ Allow**, **✗ Deny**,
**✓ Allow similar**, а внизу — быстрые действия **«Allow all safe»** (разрешить все, кроме
высокого риска) и **«Deny all»** (запретить все).

### Что если не отвечать

По умолчанию тайм-аута нет — **сессия будет ждать сколько угодно**. Через 30 секунд
баннер начинает мигать жёлтым, а если окно свёрнуто, примерно через минуту приходит
уведомление Windows. Тайм-аут можно включить в настройках (Global → Permission timeouts).

### Режимы разрешений (Permission mode)

Задаётся у сессии в **Settings → Sessions**. Возможные значения: `default`, `acceptEdits`,
`auto`, `plan`, `dontAsk`, `bypassPermissions`. Для начинающих:

| Режим | Смысл |
|---|---|
| **default** | Спрашивает почти на всё — самый осторожный |
| **acceptEdits** | Правит файлы сам, но на запуск команд спрашивает — **значение по умолчанию, хороший выбор для старта** |
| **bypassPermissions** | Ничего не спрашивает и делает всё сам — быстро, но рискованно |

### Правила авто-одобрения

Если надоело подтверждать однотипные безопасные действия, в **Settings → Sessions →
Auto-approve rules** можно задать правила. У правила три поля:

- **Tool** — инструмент: `Bash`, `Edit`, `Write` или `*` (любой);
- **Pattern** — шаблон команды или пути (например, `npm test*` или `*.go`);
- **Decision** — решение: `allow` (разрешить), `deny` (запретить) или `ask` (всё равно
  спросить).

Правила проверяются сверху вниз, срабатывает первое подходящее. Правило `ask` имеет
приоритет и всегда выводит запрос вам.

## 9. Нижняя строка состояния (Status Bar)

Слева направо показывает:

- **Active: X/Y** — сколько сессий работает из общего числа.
- **⚠ Waiting: N** — сколько ждут разрешения (появляется только если N>0; **кликабельно** —
  открывает Permission Queue).
- **Rate limited: N** — сколько под ограничением скорости (красным, если есть).
- **Errors: N** — сколько с ошибками (красным, если есть).
- **Cost today: $…** — расходы за сегодня.
- **RL: …%** — общая загрузка лимита сервиса (красным при 85% и выше).
- **Uptime: …** — сколько работает программа (справа).

## 10. «Конвейер»: как программа берёт задачи из файла

Это важный режим, в котором программа работает почти без вашего участия. Он опирается на
три настройки сессии (**Settings → Sessions → Lifecycle**):

- **Task source file** — файл со списком задач (например, `STATUS-P1.md`);
- **Stop when no tasks** — «останавливаться, когда задач нет»;
- **Auto-restart after task** — «перезапускаться после каждой задачи».

### Как это работает на самом деле

Важно понять один нюанс: **программа не вынимает из файла конкретную задачу и не
подставляет её помощнику**. Она работает так:

1. **Перед каждым запуском** проверяет файл-задач: «работа ещё есть?». Если задач нет —
   останавливается.
2. **Запускает сессию** с вашим **одним и тем же заданием (prompt)** — например,
   «Возьми следующую задачу из STATUS-P1.md».
3. **Задачу выбирает и вычёркивает сам Claude**, следуя вашему заданию.
4. Когда сессия завершилась, при включённом **Auto-restart** программа **запускает
   свежую сессию** и повторяет всё сначала.

То есть: сделал одну задачу → перезапуск → проверка файла → следующая. Так до тех пор,
пока в файле есть работа.

### Какие форматы файла понимает программа

1. **Основной (указатели).** Строки вида `файл:номер` — по одной на каждую открытую
   задачу, например:
   ```
   ROADMAP.md:92
   MIXED-TASKS.md:102
   ```
   Заголовки (`#`), цитаты (`>`) и списки (`-`, `*`, `_`) игнорируются. Задача считается
   выполненной, когда её строка удалена. Пустой файл — работы нет, цикл останавливается.
2. **Старый формат.** Файл считается «есть работа», если в нём встречается `In progress:`
   либо одновременно `Next:` и `- [`.

### Когда конвейер останавливается

- в файле не осталось задач (при включённом **Stop when no tasks**);
- достигнут лимит **Max tasks** (если задан больше 0);
- вы нажали **Stop**;
- **Auto-restart** выключён — тогда выполняется ровно одна задача и стоп.

## 11. Автоматический выбор модели

Модели стоят по-разному (opus в разы дороже haiku). Программа умеет сама подбирать модель
под сложность задачи. **По умолчанию эта функция выключена.**

Включить: **Settings → Global → Model routing → «Auto model routing»**, затем **Save**.

Что происходит при запуске сессии, когда функция включена:

1. Вы нажимаете **`▶`**.
2. Программа делает быстрый предварительный анализ задания (дешёвой моделью **haiku**),
   показывая **«Analyzing task complexity…»**.
3. Открывается окно **Start session** с рекомендацией: уровень сложности
   (**Trivial / Standard / Complex / Architectural**), пояснение и рекомендованные модель
   и effort.
4. Вы можете:
   - принять рекомендацию — кнопка **«Start with … / …»**;
   - развернуть **«Override model / effort»** и выбрать вручную (модели: haiku, sonnet,
     opus; effort: low, medium, high, xhigh, max);
   - нажать **Cancel**.

Таблица подбора (заложена в программе):

| Сложность | Модель | Effort | Типичные задачи |
|---|---|---|---|
| **Trivial** | haiku | low | форматирование, переименование, мелкие правки версий |
| **Standard** | sonnet | medium | исправления ошибок, новые небольшие функции, тесты |
| **Complex** | sonnet | high | правки во многих файлах, оптимизация |
| **Architectural** | opus | high | новые подсистемы, миграции БД, алгоритмы |

Если функция выключена, нажатие **`▶`** сразу запускает сессию с моделью из настроек.

## 12. Настройки (Settings)

Кнопка **Settings** открывает окно с четырьмя вкладками: **Global**, **Projects**,
**Sessions**, **Workers**. **Все изменения применяются только по кнопке Save** (записывается
в файл настроек). Кнопка **Close** закрывает без сохранения.

### Вкладка Global (общие)

- **General:** путь к Claude CLI, тема (**dark/light**), задержка повтора, пауза при
  ограничении скорости, срок хранения журналов, задержка между стартами сессий.
- **Crash recovery:** галочка «восстановление после сбоя» (по умолчанию включена).
- **Pre-flight analysis:** включение предварительного анализа, авто-одобрение планов из
  одной сессии, модель аналитика (по умолчанию **haiku**) и её бюджет.
- **Permission timeouts:** через сколько уведомлять, тайм-аут ответа (0 = ждать вечно),
  действие по тайм-ауту (deny / pause_session), уведомление Windows, звук.
- **Model routing:** галочка **Auto model routing** (раздел 11).
- **Budget alerts:** оповещения при превышении дневного/недельного бюджета и порог
  оповещения по загрузке лимита.

### Вкладка Projects

Список проектов и **+ Add project**. У каждого проекта: **Name**, **Path** (+ **Browse…**),
счётчик сессий и **+ Add session**, кнопка **Remove**. Здесь же — включение продвинутого
режима **Mixed programming** (см. раздел 17) с предупреждением о приватности, полем
**Gates** и числом раундов.

### Вкладка Sessions

Слева — выбор проекта и список сессий (**+ Add**, удаление крестиком). Справа — редактор
сессии:

- **Identity:** имя, **Task source file** (файл задач, раздел 10), **Prompt** (задание).
- **Model:** модель (opus/sonnet/haiku), effort, запасная модель и переключение на неё
  при ограничении скорости.
- **Permissions:** режим разрешений, списки разрешённых/запрещённых инструментов,
  правила авто-одобрения (раздел 8).
- **Lifecycle:** **Max budget USD** (0 = без лимита), **Max tasks** (0 = без лимита),
  **Auto-restart after task**, **Stop when no tasks**, **Use git worktree**, режим
  pre-flight (always/auto/never).
- **Hooks:** команды до и после задачи.
- **Crash recovery:** текст сообщения при восстановлении.
- **Context:** дополнение к системному промпту и дополнительные папки.

### Вкладка Workers

Только для продвинутого режима Mixed (раздел 17). Список воркеров, кнопки готовых пресетов
и редактор параметров подключения к внешним моделям.

## 13. История (History) и Расходы (Dashboard)

### History (История)

Таблица всех прошлых запусков. Есть фильтры: проект, имя сессии, статус, диапазон дат и
кнопка **Clear**. Колонки: **Session**, **Started**, **Duration**, **Turns**, **Tasks**,
**Cost**, **Status**. Клик по строке разворачивает подробности (токены на вход/выход,
кэш, текст ошибки, сохранённые строки журнала). Есть кнопка **Refresh**.

### Dashboard (Расходы)

Наглядная сводка затрат. Сверху выбор периода: **Today**, **This week**, **This month** и
**Refresh**. Четыре карточки: **Total cost** (всего), **Cache efficiency** (эффективность
кэша), **Avg cost per task** (средняя цена задачи), **Rate limit** (загрузка лимита). Ниже
— диаграммы: **Cost by model** (по моделям), **Cost by project** (по проектам) и **Daily
breakdown** (по дням).

> Чтобы жёстко ограничить траты по сессии, задайте **Max budget USD** в её настройках —
> помощник остановится при достижении лимита.

## 14. Что происходит само собой

Программа сама заботится о нескольких вещах — вам не нужно ничего делать:

- **Пауза при ограничении скорости.** Если сервис ограничил скорость, сессия ждёт (по
  умолчанию около 5 минут) и продолжает сама. Если у сессии задана запасная модель и
  включён переход на неё — переключится сразу, без паузы.
- **Восстановление после сбоя.** Если программа была неожиданно закрыта, при следующем
  запуске сессия может продолжить прежний разговор с того места, где остановилась.
- **Контроль контекста.** Когда «память» разговора заполняется примерно на 60%, вы
  получаете предупреждение; около 75% сессия автоматически перезапускается, чтобы не
  переплачивать и не терять качество.
- **Защита от зацикливания.** Если помощник повторяет одно и то же действие (по умолчанию
  3 раза подряд среди последних 20), программа это замечает и предупреждает.

## 16. Если что-то пошло не так

**Сессия стоит в статусе waiting_permission.** Она ждёт ответа на запрос разрешения.
Найдите баннер в окне сессии или откройте Permission Queue (клик по «⚠ Waiting» внизу) и
нажмите Allow или Deny.

**Помощник «задумался» и молчит.** Возможно, сработало ограничение скорости (статус
rate_limited) — обычно продолжит сам после паузы. Если нет — нажмите **Restart**.

**Настройки не применились.** Убедитесь, что нажали **Save**, а не просто закрыли окно.

**Статус error.** Посмотрите последние строки журнала — там обычно причина. Часто помогает
**Restart**. Если повторяется — сохраните журнал кнопкой **Export log** и покажите
специалисту.

**Деньги уходят быстрее, чем ожидалось.** Проверьте модель (opus самый дорогой), включите
авто-выбор модели (раздел 11) и задайте **Max budget USD** у сессии.

**Случайно удалили проект.** Последняя сохранённая версия настроек лежит в файле
`C:\Users\ваше-имя\.claude-manager\config.toml`. Обратитесь к техническому специалисту.

## 17. Продвинутый режим Mixed

Кнопка **Mixed** в верхней полосе открывает продвинутый режим «смешанного
программирования». В нём Claude готовит подробное задание, а **другие, более дешёвые
внешние модели** пишут по нему код в виде правок. Программа применяет эти правки в
изолированной копии проекта, прогоняет автоматические проверки (**gates** — например,
сборку и тесты) и, если что-то не так, отправляет модель на доработку — по умолчанию до
**3 раундов**. В конце показывается сравнительный отчёт по качеству разных моделей.

**Важно про приватность.** Этот режим **отправляет фрагменты вашего кода во внешние
сервисы, которые сохраняют запросы**. Поэтому он выключен по умолчанию, а при включении
программа показывает предупреждение. Чтобы его задействовать, нужно: включить
**Mixed programming** у проекта, задать хотя бы одну проверку (**Gates**) и настроить хотя
бы одного воркера на вкладке **Workers** (есть готовые пресеты). Ключи доступа берутся из
переменных окружения и в настройках не хранятся.

**Начинающему пользователю этот режим не нужен** — его обычно настраивает специалист.
Спокойно проходите мимо кнопки Mixed, если не уверены.

## 18. Словарик

- **Проект** — папка, над которой работает помощник.
- **Сессия** — один запущенный помощник с заданием.
- **Prompt (задание)** — текст с описанием, что сделать.
- **Модель (haiku / sonnet / opus)** — «мозг» помощника: от дешёвого к дорогому.
- **Effort** — тщательность размышления (low…max).
- **Permission (разрешение)** — согласие на действие помощника.
- **Permission mode** — режим самостоятельности (default / acceptEdits / bypassPermissions
  и др.).
- **Rate limit** — временное ограничение скорости со стороны сервиса.
- **Gates** — автоматические проверки кода (сборка, тесты) в режиме Mixed.
- **Токены** — единицы объёма текста; от них зависит стоимость.
- **Контекст** — «память» текущего разговора; когда заполняется, сессия перезапускается.

---

Начните с малого: один проект, одна сессия с простым заданием, режим **acceptEdits**,
кнопка **`▶`** — и понаблюдайте за «прямым эфиром». На практике всё станет понятно.
